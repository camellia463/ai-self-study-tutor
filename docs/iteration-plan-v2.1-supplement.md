## 一、时间能量地图 · 详细多维度设计（v2.0 §1.2 的细化）

### 1.1 核心：可解释的能量计算模型

**能量等级 E(t) = 昼夜节律基线 B(t) + 活动后效应 A(t) + 个体修正 P**

每个时刻的能量是三个因子叠加算出来的，**不是拍脑袋**，这样才能回答评委"为什么排这个时间"。

### 1.2 因子一：昼夜节律基线 B(t)（默认模板，可按学生作息微调）

| 时段 | 基线值 | 生理依据 |
|---|---|---|
| 06:00-08:00 | +2 | 睡眠后清醒，皮质醇峰值 |
| 08:00-11:00 | +1 | 上午高效期 |
| 11:00-14:00 | -1 | 午间低谷（含午饭后） |
| 14:00-17:00 | +1 | 下午回升 |
| 17:00-19:00 | 0 | 傍晚平稳 |
| 19:00-21:00 | +1 | 晚间小高峰 |
| 21:00-23:00 | -1 | 睡前下降 |

### 1.3 因子二：活动后效应 A(t)（学生标注活动后叠加）

| 活动 | 效应 | 依据 |
|---|---|---|
| 有氧运动后 30-90min | +2 | 促进 BDNF，学习记忆增强（用户点名的"运动后激活"） |
| 饭后 30-60min | -2 | 血液流向消化系统，脑供血下降 |
| 长时间高强度脑力后 | -1 | 认知疲劳 |

### 1.4 因子三：个体修正 P（学力维度联动）

| 学力维度 | 修正效果 |
|---|---|
| 工作记忆弱 | 单块压到 25min + 5min 休息（防遗忘溢出） |
| 加工速度快 | 单块可到 45min（不易疲劳） |
| 学习能力 | 决定单日总认知负荷上限 |

### 1.5 能量 → 任务类型映射（最终落点）

| 能量等级 | 排什么 | 具体任务 |
|---|---|---|
| E ≥ 3 巅峰 | 攻克 | 新概念、难题、真变式 |
| E = 1~2 高效 | 练习 | 刷题、巩固 |
| E = 0~1 平稳 | 常规 | 常规学习 |
| E ≤ 0 低效 | 复习 | 错题回访、SM-2 记忆 |
| 不可用 | 不排 | 上课/补习/作息 |

### 1.6 输出：精准到时刻的时间表

每天 48 个半小时槽（07:00-23:00 学习窗口内），每槽输出：
`{ 时间段, 能量等级, 任务类型, 具体知识点 }`

例：`周二 19:30-20:15 [⚡高] 攻克·空间向量数量积`

**数据结构**：`schedule_plan.time_map` = `{ date: { "19:30": {energy: 3, task: "attack", kpId: "math-g2-002"} } }`

## 二、概念可视化 · 放弃 3D，改用可靠 2D（v2.0 §5.1 修正）

**决策：不用 Three.js / 3D 渲染**（WebGL 兼容、SVG 投影易出问题）。

**替代方案：斜二测投影 2D SVG**（高中数学课本标准画法，学生一看就懂）

- 3 根轴：x 水平向右，y 向前偏 45°，z 竖直向上——这是课本画空间向量的标准视角
- 空间向量 = 2D 平面里的一根带箭头线段（起点 + 沿三个轴的投影虚线）
- **可交互**：滑块拖动向量分量 (x,y,z)，箭头实时移动，结果实时更新
- 纯 SVG + 内联坐标计算，无 WebGL、无兼容问题、渲染 100% 稳定

**保证直观不出错的手段**：
1. 全部用斜二测投影（不碰透视投影，避免视觉误差）
2. 向量画成"实线箭头 + 三个轴的虚线投影框"，学生能看清三个分量
3. 交互用滑块（离散值），不用自由拖拽（避免角度误判）
4. 关键结论配"图 + 公式"并排卡

**具体操作由开发定，验收标准 = 直观 + 零渲染错误**（用户原话："你来讲，我不负责，我只负责直观不出错"）。

## 三、漫画翻译 · 选择性做 + 先做高一 + "为什么"

### 3.1 漫画选择性做（控制 token）
- 只对**最抽象的 2-3 个概念**用 SVG 漫画分镜，其余用文字类比（省钱）
- 漫画候选：向量的"方向+大小"、数量积的"合力效果"、共面定理的"躺进同一平面"

### 3.2 先做高一的一部分内容
- 内容范围从"空间向量（高二）"**前移**，先做高一数学必修第一册的**一部分**（集合、函数概念、单调性等基础章节）
- 理由：用户教的学生是高一的，且高一内容是基础，零基础学生从这里进

### 3.3 每个知识点必须讲"为什么"
在 v2 内容结构（goal/prerequisites/concepts/workedExample/questions）基础上，concepts 每一条增加 `why` 字段：
- **是什么（what）** → **为什么是这样（why）** → **怎么做（how）** → **怎么写（符号）**
- 例：为什么向量加法用"首尾相接"？→ 因为向量是"位移"，走 A→B 再 B→C，总位移就是 A→C，首尾相接正是位移的叠加
- 目标：让学生"看到为什么是这样的知识"，理解原理而非死记

## 四、学生数据 · 差异化战略（长期护城河）

**用户优势**：手上有一批真实学生的提分/自学数据（后续单独发聊天记录）。

### 4.1 战略定位
市面 AI 辅导软件是**通用模型**（同一套模板给所有人）；用户有**真实学生数据**，能做到"更懂真实学生的卡点"。

### 4.2 黑客松 72h 内能做的（务实边界）
1. **数据背书噱头**："基于 N 个真实学生的提分数据迭代"——首页/关于页一句可信的差异化声明
2. **数据接口预留**：`student_insight` 表 + 导入脚本，后续把聊天记录结构化导入
3. **卡点库雏形**：把学生高频错误/卡点整理成"错因树"的补充数据源

### 4.3 后续（单独对话框）
学生聊天记录 → 结构化提取 → 训练诊断/排课模型 → 真正的数据飞轮。

**关键判断**：黑客松 72h 不碰真训练，做"背书 + 接口预留"，数据优势作为**长期叙事**而非短期功能。

## 五、噱头设计 · 核心功能 vs 噱头分层

### 5.1 分层原则
- **核心功能**（真正价值，不能垮）：诊断→排课→教学→复习→监管闭环、时间能量地图、动态重排
- **噱头**（博眼球 + 演示放大器，服务于核心，不喧宾夺主）

### 5.2 噱头清单（按博眼球力排序）

| 噱头 | 形式 | 技术支撑 |
|---|---|---|
| ⚡ 能量热力图 | 一周 7×48 时间槽渲染成热力图（像 GitHub 贡献图），一眼看到"你的黄金时间" | SVG 网格 + 能量模型数据 |
| 🤖 AI 排课师人格化 | 排课结果配人话解释："我发现你周四游完泳状态最好，把最难的数量积排在那之后" | 决策 reason 字段 + 话术模板 |
| 🔄 追进度动态重排动画 | 勾选"今天没完成"→ 动画展示 AI 把任务挪到明天、怎么让位 | reschedule 算法 + 前端过渡动画 |
| ⏳ 提分倒计时仪表盘 | 首页顶部"距高考 287 天 · 还差 65 分 · 今天要涨 0.23 分" | 目标模型 + 进度计算 |
| 📊 数据背书 | "基于 N 个真实学生数据迭代" | 学生数据战略 |

### 5.3 关键判断
- 噱头里**"能量热力图"和"追进度动画"性价比最高**——既是视觉爆点，又直接展示核心功能（能量地图、动态重排）
- "AI 人格化"要克制，一句话解释即可，过度拟人会显廉价

## 六、技术端强化 · 评委视角

评委看技术，加分点排序：

1. **决策可解释（Explainable Scheduling）**：每个排课决策带 `reason`，前端可点开看"为什么排这个时间/这个知识点"——技术含量 + 差异化
2. **WebSocket 实时推送**：到点提醒、进度实时同步（socket.io）
3. **调度算法纯函数模块化**：`scheduler.js` 拆成可单测的纯函数（能量计算、优先级排序、重排各自独立）
4. **数据可视化引擎**：能量热力图、知识图谱、学力雷达图
5. **测试覆盖**：调度算法单元测试 + 全链路冒烟测试

**架构原则**：简约但有深度。评委喜欢"清晰的四层架构 + 可解释的调度算法"，讨厌堆砌微服务。
