# AI 自学提分平台 · 迭代方案 v2.0（换模型开发依据）

> 日期：2026-08-24
> 状态：待确认后全自动闭环开发
> 前置：v1 已交付（登录持久化 + 聚焦单点 + 零基础教学），本文档是 v2 迭代需求

---

## 背景：用户 6 点反馈（原始诉求）

1. UI 设计可后期优化（导航栏+内容区架构 OK）
2. 学习目标设定不明确——没明确固定时间、每天学多少、投入多少精力、收获多少分；目标考试要明确；生成周计划前要询问本周哪些时间可用/不可用/可加倍利用；考虑节律因素（运动后学习大脑激活、饭后效果差）
3. 周计划要监管——任务没完成要从当天别的时间或明天补，保证进度不落；总调控：①调控时间间隔和精度 ②时间被占用后的重分配
4. 学力筛选更细化——学习能力维度产生链接，反向倒推设置周计划
5. 知识图谱无法点击（bug）
6. 细化讲解过程——概念配 3D 图/漫画，图文融合，零基础快速学明白、可掌握；以练代学；变式不是变数据
7. 技术栈/架构要更高级、简约、有技术含量（黑客松会考）
8. 网络安全——防火墙、API 防攻击、扛住攻击

---

## 一、目标设定明确化（第 2 点，最大改造）

### 1.1 目标建模（SMART 化）
- `targetExam` 从自由文本 → 结构化下拉（高考/月考/期末/中考），自动算剩余天数
- 新增 `currentScore`（当前基线，学生填最近一次真实分数 或 由诊断反推）
- 系统算出并展示：`差距 = 目标分 - 当前分`，`每天需涨 = 差距 ÷ 剩余天数`
- 给出一句可感知承诺：**"你要在 N 天内涨 X 分 = 每天 Y 分，折合每天 Z 个知识点的稳定推进"**

### 1.2 时间能量地图（生成周计划前的必答问卷）
生成周计划前弹"时间采集器"，只问 3 件事，7×24 网格点选：
1. ❌ 固定不可用（上课/补习/作息/吃饭）
2. ✅ 可用（空闲整块）
3. ⚡ 黄金时间（运动后/早晨清醒）

默认规则：饭后 30min = 低效时段。

### 1.3 节律排课（能量 → 任务类型映射）
| 能量 | 触发 | 排什么 |
|---|---|---|
| ⚡高 | 运动后/早晨 | 攻克（新知识、难题、变式） |
| ✅中 | 一般空闲 | 练习（刷题巩固） |
| 🔋低 | 饭后30min | 复习（错题回访、SM-2 记忆） |

输出：每天精确到时刻的时间表。

**数据模型变更**：`schedule_plan` 新增 `time_map` 字段（JSON，7×24 能量网格），`week_data` 的 block 新增 `time_slot` 字段。

## 二、周计划总调控（第 3 点）

### 2.1 调控层 1：时间间隔与精度
- 单块时长按学力自适应（见第四节），25-45min 番茄钟
- 每 block 绑定具体 `time_slot`

### 2.2 调控层 2：未完成补偿调度（核心）
- block 状态 `skipped` → 触发 `reschedule()`：
  1. 扫当天剩余高能量槽 → 塞进去
  2. 当天补不完 → 明天让位（降明天低优先级 block，插补学任务）
  3. 核心知识点（高权重×高薄弱）标记"不可跳过"
- 写 `adjust_history`，前端可视化

**实现**：`scheduler.js` 新增 `reschedule(plan, completedLogs, timeMap)`，`complete-block` 接口调用它返回更新后的计划。

## 三、学力维度反向倒推排课（第 4 点）

建立映射表，让 5 个认知维度驱动排课参数：

| 认知维度 | 反向倒推参数 |
|---|---|
| 加工速度 processingSpeed | 单块时长：快45min/慢25min |
| 工作记忆 workingMemory | 复习间隔：弱→SM-2缩短，强→拉长 |
| 流体推理 fluidReasoning | 教法起点：强→演绎，弱→类比/拆解 |
| 认知灵活性 cognitiveFlexibility | 变式跨度：灵活→大跨度，僵化→小步 |
| 学习能力 learningAbility | 单日推进速度 |

**实现**：`scheduler.js` 入参新增 `learnerProfile`（认知维度），内部计算排课参数。

## 五、图文融合 + 真变式（第 6 点）

### 5.1 3D 可视化
- Three.js（WebGL）做 3D 可交互图：空间向量坐标/加减/数量积夹角
- 核心概念配"图+公式"融合卡

### 5.2 漫画翻译
- 抽象概念用 SVG 漫画分镜（对话气泡+分格）翻译

### 5.3 以练代学 + 真变式
- 变式三型：结构变式 / 方法变式 / 情境变式（不是换数据）
- 每道变式标注"变在哪"，错因树同步升级

**数据模型变更**：`vector-content.js` 的 concept 新增 `visual`（3D/漫画类型），question 新增 `variation_type`（structure/method/context）。

## 六、技术架构（第 7 点，已画图）

四层架构：
1. 前端层：React + Vite + TS + Zustand + TanStack Query
2. 安全网关：Helmet + Rate Limit + CORS 白名单 + zod + 请求体限流
3. 应用层：Controller → Service → Repository 三层拆分
4. 数据层：SQLite（WAL）+ node-cache 缓存

---

## 七、网络安全（第 8 点，纵深防御）

1. 应用层：Helmet + express-rate-limit + 请求体大小限制 + zod 全路由校验
2. 认证层：scrypt + token 过期 + 登录失败次数限制（防撞库）
3. 数据层：SQL 参数化 + React 默认转义
4. 网络层：后端只监听 127.0.0.1 + CORS 严格白名单；部署 Nginx + fail2ban
5. 演示：wrk/ab 压测展示 429 限流拦截
